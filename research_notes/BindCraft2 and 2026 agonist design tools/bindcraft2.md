# BindCraft2 v1.0.4 — profile for de novo GLP1R (class B GPCR) agonist design

> Scope note: profiling BindCraft2 (BC2) as a design *tool* for a de novo linear peptide / mini-protein that engages the **active-state GLP1R 7TM vestibule**. Per the project firewall, class-B agonism is UNPROVABLE/UNRANKABLE in-silico; nothing below proposes an agonism score. "Induced-fit" is treated strictly as binder-side geometry/mechanism-biasing. Repo located at **github.com/PacesaLab/BindCraft2** (434 stars at time of search). Research done 2026-10-19; **v1.0.4 was published the same day (2026-10-19)**, so this is the brand-new current release.

## Q1. What is BindCraft2, and what does v1.0.4 specifically add (VHH / scFv / ARP / induced-fit)?

### Takeaway
BindCraft2 is the second-generation, ground-up rewrite of the BindCraft de novo binder pipeline (Pacesa, now Univ. Zurich), versioned fresh from v1.0.0 (2026-09-16). It generalises the original miniprotein-only tool into a multi-modality binder suite (de novo miniprotein, VHH, scFv, Fab, ARP/ankyrin, linear + cyclic peptide, plus conformational objectives induced_fit and fold_switch). **v1.0.4 is a focused release (2026-10-19) whose headline is "Fold switching and induced fit modality improvements"** plus explicit-paratope antibody design and confidence-masked scoring. NOTE: the original BindCraft (martinpacesa/BindCraft, at v1.5.3) is a *separate* repo — do not confuse the two version lines.

### Cited Findings
- Repo and identity: top GitHub hit for "BindCraft2" is **PacesaLab/BindCraft2**, 434 stars, described as a user-friendly suite for designing many kinds of protein binders — [GitHub search](https://github.com/search?q=BindCraft2&type=repositories).
- README positioning: BC2 "combines sequence optimisation through AlphaFold 2 with ProteinMPNN redesign" and "evaluates candidates with separate AlphaFold models" — [README](https://github.com/PacesaLab/BindCraft2).
- Release line (all 2026, confirmed via API `published_at`): v1.0.0 2026-09-16 ("Initial public release of BindCraft2"); v1.0.1 2026-09-21 (hotfix, multi-chain monomer-repredict indexing error); v1.0.2 2026-09-24 (community PRs: nvidia-smi installer fix, 1-based binder residue numbering, aa_bias fix, external docs site); v1.0.3 2026-09-26 ("Updated scaffold design definitions"); **v1.0.4 2026-10-19** — [GitHub releases](https://github.com/PacesaLab/BindCraft2/releases); [releases API](https://api.github.com/repos/PacesaLab/BindCraft2/releases).
- **v1.0.4 changelog (verbatim/near-verbatim):** headline "Fold switching and induced fit modality improvements"; "scoring is now performed only on confidently folded residues"; new `fold_switch_delta` RMSD-based objective (fold-switching was previously driven by TM-score alone); defaults changed — `weights_interface_contacts` 1.0→2.0, `min_induced_fit_interface_rmsd_final` 5.0→2.0, `max_induced_fit_tm_final` 0.6→0.85; antibodies "should bind through the CDRs rather than through the framework"; framework positions next to CDRs now marked with `!` in `mutate_positions` so they stay fixed but can still contact the target; when several modality flags are set "we have hand tuned the settings so that intent is preserved"; faster memory management for large complexes; cluster-friendly campaign handling — [GitHub releases](https://github.com/PacesaLab/BindCraft2/releases); [releases API](https://api.github.com/repos/PacesaLab/BindCraft2/releases).

## Q2. "Induced-fit targeting" — operational meaning; is it binder-side or target-conformation; can it hit a 7TM vestibule?

### Takeaway
**`induced_fit` is BINDER-SIDE: it optimises the designed binder's *own* binding surface to change shape between its free and bound states (fold-/shape-upon-binding), judged by binder free-vs-bound interface RMSD and TM-score. It does NOT induce or stabilise a specified *target* conformation.** The target is supplied as **exactly one fixed structure** that BC2 "freezes" and designs against — so you control which receptor conformation is engaged by *choosing the input PDB* (e.g., an active-state GLP1R 7TM coordinate set), not by any induce-the-target mechanism. This maps cleanly onto the project firewall: induced_fit is geometry/mechanism-biasing of the *binder*, never a target-activation score.

### Cited Findings
- README definition: induced_fit = "A conformational objective for a binder whose binding surface changes shape between free and bound states" — [README](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/README.md).
- reference.md: "`induced_fit` requests movement of the binding surface" and "requires exactly one target"; it "freezes one bound structure to compare a free state against" — [reference](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/reference.md).
- Modality table: induced_fit "Choose it when: The binder should change shape on binding"; "What it makes: The interface is optimised toward a 5 Å shift free vs bound and accepted above 2 Å"; a Binder_RMSD gate was switched off because it "measures the very displacement they exist to create" (i.e., the binder's own backbone is what moves) — [modality guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide/03-choosing-a-modality.md).
- One ambiguous phrase, flagged: the modality table's "Typical applications" column says induced_fit is for "Binders for targets that change shape on binding (conformational selection), and allosteric or state-selective binders" — this describes the *use case* (targets that happen to be flexible), while every mechanistic/scoring statement describes the *binder's* shape change — [modality guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide/03-choosing-a-modality.md).
- Acceptance gates (v1.0.4): `min_induced_fit_interface_rmsd_final` default 2 Å "require movement of the binding surface"; `max_induced_fit_tm_final` default 0.85 "require a whole-fold change" — these compare the binder's free vs bound states — [reference](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/reference.md); [releases API](https://api.github.com/repos/PacesaLab/BindCraft2/releases).
- Target conformation is user-supplied and templated: `targets[].target_path` accepts "PDB, mmCIF or FASTA" and should "Supply a structure or sequence target"; `weights_target_rmsd` (default off) = "Keep the target close to the supplied coordinates"; `weights_target_rigidity` (default off) = "Keep a receptor assembly's chains in their supplied arrangement"; `target_flexibility` (default 0) = "Fraction of templated target residues whose sequence and sidechain information are withheld, while retaining their backbone" (i.e., sidechain/sequence masking, NOT backbone freedom) — [reference](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/reference.md).
- Multi-state machinery exists but is binder/epitope-oriented: `binder_shapes` = "Define explicit conformation groups" (example `[["hPDL1"],["binder_alone"]]`); `idr_crop_count` = "Number of sequence windows treated as separate target states"; `targets` list can "Supply your own proteins, receptor assemblies or off-targets" — [reference](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/reference.md).
- Pocket/groove suitability (relevant to a 7TM vestibule): peptide modality = "A short linear peptide into a groove or pocket — not a flat surface," targets "active-site channels" / "groove or cleft"; VHH targets "enzyme active sites, clefts, pockets, cryptic sites"; design guide: "grooves and pockets want an extended peptide or VHH CDR3" — [design guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide.md); [modality guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide/03-choosing-a-modality.md).
- Membrane/GPCR context: "BC2 designs against what you give it, membrane and glycan context included or not"; for cell-surface targets, "consider glycans, membrane orientation and access by other proteins" — [design guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide.md); [README](https://github.com/PacesaLab/BindCraft2).

### Inferences
- For GLP1R: operationally you would (a) supply the **active-state 7TM coordinates as the single target** (optionally with membrane/lipid/glycan context stripped or kept), templated/frozen to that conformation, and (b) design a **linear peptide (12–25 aa) or VHH-CDR3-style extended loop into the vestibule pocket**, optionally with `induced_fit` to let the *binder* fold-on-binding into the groove. This biases binder geometry toward a vestibule-engaging pose — it does NOT, and cannot, score agonism.
- induced_fit is the right *mechanism-biasing* lever (binder shape-complementarity to a deep pocket), consistent with the firewall; it must not be reported as evidence the design will *activate* the receptor.
- The 7TM vestibule is effectively a deep pocket/groove → the docs' own guidance ("grooves and pockets want an extended peptide or VHH CDR3") points at the peptide modality, which also satisfies the project's linear/natural-AA/no-disulfide constraints (VHH/scFv/ARP are disulfide-bearing folded domains, not linear peptides).

### Gaps
- The docs never state explicitly, in one sentence, "the binder (not the target) changes shape." Reading is inferred from 4+ convergent mechanistic statements; one "Typical applications" phrase is ambiguous. Confidence high but not author-confirmed.
- **No published GPCR / 7TM / membrane-protein / vestibule design result anywhere** in BC2 docs or search — GPCRs are never named. Whether AF2 co-folding reliably places a de novo peptide in a class-B 7TM vestibule is untested/undocumented here.

## Q3. CRITICAL — structure model + weights + license → GO/NO-GO for submission eligibility

### Takeaway
**PROVENANCE = GO (eligible).** BC2's entire design/validation stack is **AlphaFold 2 + ProteinMPNN (with HyperMPNN weights for the "positive" design term)**. There is **no AF3, no Protenix/Protenix-v2, no ESM, no ESM-3, no ESMC** anywhere in the pipeline. AF2-based provenance is explicitly acceptable per project rules, so sequences designed with BC2 v1.0.4 are eligible to publish under ODC-BY. **LICENSE = clean for this use.** BC2 ships under a bespoke "Source-Available (Hosting-Restricted)" license that *explicitly permits sharing design outputs (sequences/binders/structures)*; the only restriction (no third-party hosted SaaS/API; no "BindCraft2" trademark use) does not touch local design-and-submit.

### Cited Findings
- Models: README names **AlphaFold 2** and **ProteinMPNN**; BC2 "uses AlphaFold 2 code and models for both sequence optimisation and validation"; the "positive" design weights come from **HyperMPNN**; ESM / ESMC / AF3 / custom networks are not mentioned — [README](https://github.com/PacesaLab/BindCraft2); [README raw](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/README.md).
- Weights count: a campaign uses **seven AlphaFold models — five multimer models for design + two monomer models for validation** (i.e., standard AF2/AF2-multimer params) — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- AF2 params provenance: 5.3 GB parameter archive downloaded on first use to `BINDCRAFT_AF2_PARAMS` (default `~/.cache/bindcraft/alphafold`), or pre-fetched with `bindcraft fetch-weights` — standard DeepMind AF2 parameters (host not named in docs) — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- **License identity:** "BindCraft2 Source-Available License (Hosting-Restricted)", "Copyright (c) 2026 Martin Pacesa, University of Zurich, and the BindCraft2 contributors" — [LICENSE](https://github.com/PacesaLab/BindCraft2/blob/main/LICENSE).
- License terms: free use for any purpose incl. internal commercial; may modify/derive/redistribute source or binaries; running on your own/private infra is allowed and **"you can share design outputs such as binders, sequences, or structures"**; offering it as a hosted SaaS/API/agent-action to third parties needs a separate commercial license (unless the third party installs it themselves); "BindCraft2" name is a Univ. Zurich trademark and can't be used to market a hosted service/derivative; termination on violation with 30-day cure — [LICENSE](https://github.com/PacesaLab/BindCraft2/blob/main/LICENSE).

### Inferences
- **GO/NO-GO verdict: GO.** No banned model (AF3/Protenix-v2/ESM-3/ESMC-600M) is in the design provenance; AF2-multimer + monomer + ProteinMPNN/HyperMPNN is squarely in the "AF2-based is acceptable" bucket. BC2 v1.0.4 designs are submission-eligible under ODC-BY.
- HyperMPNN is a ProteinMPNN *re-weighting/retraining* (same GNN inverse-folding architecture, not a protein language model and not ESM-derived), so it introduces no banned-model provenance — stated with high confidence but the HyperMPNN lineage was not independently re-verified this session.
- License is permissive enough for the challenge: you run BC2 locally on the DGX, keep outputs, and publish the winning sequences — all explicitly allowed. The hosting-restriction and trademark clauses are irrelevant to a local design campaign. (Note the change from the original BindCraft's plain MIT: BC2 is *not* MIT.)

### Gaps

## Q4. Hardware / throughput; fixed vs flexible receptor; published GPCR / membrane / peptide results

### Takeaway
BC2 is a standard JAX/AlphaFold2 GPU workload: runs on a single modern NVIDIA GPU (compute capability ≥7.5 for the CUDA-13 wheels; older Volta/Pascal/Maxwell via CUDA-12; AMD via ROCm 7), memory scaling ~O(N²) with padded complex length, and parallelises across workers/GPUs and Slurm clusters. **The receptor is templated/frozen to the supplied coordinates by default (not flexed); `target_flexibility` only masks target sidechain/sequence while keeping the backbone.** No GPCR/membrane/7TM result is published; peptide (12–25 aa linear) is a first-class modality.

### Cited Findings
- GPU: CUDA-13 wheels need "compute capability 7.5 or newer"; older Volta/Pascal/Maxwell use CUDA-12 wheels; AMD via `bash install.sh rocm` against "a local ROCm 7 installation" — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- Memory model: planner estimate "2.0 × (3.4 GB + 38 kB × N²) per worker" (N = padded complex length) → ~7.1 GB at 64 residues, ~26.7 GB at 512; capacity table spans L4 24 GB (one worker up to padded 416), A100 40/80 GB, L40S/RTX 6000 Ada, H100, GH200, H200 — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- Host/cluster: Slurm sizing "4 cores and 24 GB per GPU"; containers build for x86-64 and aarch64 (Docker/Apptainer/enroot); "Allow about 20 GB of free space" (5.3 GB param archive + unpacked + wheels + results) — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- Throughput: "On a GH200 a forty-trajectory campaign took 3620 s at one worker and 2021 s at seven"; prediction shape "about 60 s to compile and 1.5 s to read back" (compiled-graph cache) — [installation](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/installation.md).
- Receptor handling: default templated to supplied coordinates (`weights_target_rmsd` "Keep the target close to the supplied coordinates", off by default; `weights_target_rigidity` "Keep a receptor assembly's chains in their supplied arrangement", off by default); `hard_target` "Start the re-prediction of each redesigned candidate from the pose the trajectory folded"; `large_complex_initialization` "start the gradient stages from the coordinates on hand, so the target begins folded in its own frame"; `target_flexibility` withholds "sequence and sidechain information… while retaining their backbone" (default 0) — [reference](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/reference.md).
- Peptide modality specifics: "A 12–25 residue linear peptide, judged bound without a free fold"; cyclic_peptide "A 7–20 residue head-to-tail cyclic peptide"; a scaffold modality combined with `cyclic_peptide` is a contradictory combo BC2 refuses at start-up — [modality guide](https://raw.githubusercontent.com/PacesaLab/BindCraft2/main/docs/source/design-guide/03-choosing-a-modality.md).
- Original BindCraft (for induced-fit lineage): "BindCraft co-folds the target and binder to improve designs by allowing levels of induced fit" and "requires… AlphaFold at every iteration step" — [GenEngNews](https://www.genengnews.com/?p=319885).

### Inferences
- Fits the local 8×H100 DGX trivially: a 40-trajectory peptide campaign is ~30–60 min, and seven workers across a node cut it to ~34 min on GH200-class hardware; H100s are in the supported table. Short peptides (12–25 aa + a ~GLP1R 7TM target of a few hundred residues) sit well under the 24 GB-per-worker regime, so many parallel workers per GPU are feasible.
- **The receptor does not "induce-fit" to the binder by default** — it is held at the input conformation. To engage the *active-state* vestibule you must feed the active-state structure; BC2 will not morph an inactive input into an active pocket. This reinforces that "induced fit" is binder-side.
- Linear-peptide-into-a-pocket is exactly the documented sweet spot for the `peptide` modality, and it is the only BC2 modality that matches the project's linear + natural-AA + no-disulfide constraints.

### Gaps
- No per-design wall-clock or success-rate numbers for peptides or for any membrane/GPCR target; the only throughput figure is a 40-trajectory GH200 campaign total.
- No documented validation that AF2 co-folding reliably docks a de novo peptide into a class-B GPCR 7TM vestibule (GPCRs never appear in docs or search).
